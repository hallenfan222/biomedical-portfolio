# Eye Sentinel：青光眼筛查与人工复核

**Glaucoma screening & selective review | Project proposal / 项目方案**

[返回作品集](../../README.md)

**状态：方案设计与建模准备。尚无最终实验结果；此页是项目概述，不是可运行系统。**

## 做了什么

本项目聚焦**青光眼**筛查中的人工复核分配：当人员只能复核一部分样本时，如何选择更值得复核的样本，并用一致标准评价策略差异。

项目把模型性能与实际流程约束放在同一框架中考虑。仅比较分类准确率不能回答“有限复核能力应分配给谁”，因此方案明确固定复核预算，再比较复核后的漏检情况。

## 本人贡献

参与整体研究问题与方向制定、数据处理及代码撰写、建模与比较方案讨论，并参与成果展示和汇报。围绕图像质量、预测不确定性与人工复核的关系，参与整理评价逻辑和实验计划。

这是课程团队项目，以上描述本人参与的环节。下面的模型评价与复核效果仍属于计划，不视为本人或团队已经取得的结果。

## 怎么做：拟定评价方案

| 环节 | 计划开展的工作 | 对判断的作用 |
| --- | --- | --- |
| 定义筛查任务 | 明确青光眼目标标签、数据来源与适用人群 | 避免将其他眼病识别结果混作青光眼效果 |
| 数据准备 | 核对标签、重复样本与图像质量；按可用身份信息避免同一受试者跨集合 | 降低重复样本与数据泄漏带来的偏差 |
| 模型开发 | 在训练 / 验证数据上建立分类基线，确定阈值与候选复核评分 | 将参数选择与最终评价分开 |
| 固定资源约束 | 在相同 **10% 复核比例**下比较候选策略 | 保证不同策略使用同等复核资源 |
| 评价收益与代价 | 比较剩余漏检数、敏感度、误报及被复核样本构成 | 说明改善发生在哪里，以及付出的代价 |

候选策略围绕预测不确定性、图像质量以及两者结合展开。最终策略与评分方式需由数据分析确定；此处不预先宣称某一策略更好。

## 预计结果与交付物

- 形成可复核的数据处理、训练与评价流程，以及策略选择的依据。
- 在同一测试划分、同一 10% 复核预算下形成策略对照表，量化漏检、误报与复核资源之间的关系。
- 给出适用范围、误差案例与下一步验证建议，用于团队展示和汇报。

**不预设漏检一定下降，也不填写尚未测得的改善百分比。** 这些是预计形成的交付物，不是已经验证的性能承诺。

## 关键限制

离线评价必须交代复核后的标签如何获得。若用真实标签替代人工判断，只能视为“理想复核”假设，不能等同于真实医生复核效果。真实应用还需要验证复核准确性、耗时、不同机构数据表现和工作流程可行性。

本页没有发布患者影像、原始课程数据或完整团队材料；也不提供诊断建议或宣称临床部署。

**English summary.** Eye Sentinel is a glaucoma-focused proposal examining which samples to prioritize for manual review under a fixed 10% review budget. I contribute to problem formulation, coding/data processing, evaluation planning and presentation. The planned output is a transparent comparison of missed cases and review trade-offs. No completed experiment, clinical benefit or deployment is claimed.
